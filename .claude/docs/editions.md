# 원작판 / 개선판 구조 (검토안, 2026-10-12)

목표: 같은 엔진 위에서 **원작판**(원작 재현)과 **개선판**(장면 재구성·현대어 대사·재설계 시스템)을 모두 실행. 공통 부분을 최대한 같이 쓴다.

## 결론: 브랜치가 아니라 한 코드베이스 안의 "에디션"
- 브랜치 두 개 (original / remake) 는 추천하지 않는다. 엔진 수정(렌더·입력·버그)이 두 브랜치에 계속 옮겨져야 하고,
  지금처럼 main.ts 한 파일에 섞여 있으면 매번 충돌한다. 브랜치는 지금처럼 기능 단위로만 쓴다.
- main 하나에 `src/editions/original`, `src/editions/remake` 를 두고, 타이틀 화면(또는 `?ed=`)에서 고른다.
  배포도 하나 (같은 URL 에서 두 판 선택). 에디션 코드는 dynamic import 로 나눠, 고른 판만 받는다.

## 나누는 선
| 층 | 공통 (core) | 에디션별 |
|---|---|---|
| 자원 | 원작 추출물 `public/assets` (맵·스프라이트·초상화·효과음·데이터 표) | 개선판의 추가 자원 (새 맵 배치, 새 초상화가 생기면) |
| 엔진 | 캔버스 렌더, 카메라, 입력, 이동 경로·범위 계산, 애니메이션, 대화 재생기, 메뉴 UI 틀, 세이브 저장소 | — |
| 전투 규칙 | 규칙 **인터페이스** (`Rules`) | 피해·명중·반격·지형 보정, 행동 순서 (원작: 민첩 키 개별 순서 [확정 공식] / 개선: 재설계), 경험치·레벨업, 마법·피로, 전직 |
| AI | 탐색 도우미 (도달 범위·공격 칸) | 대상 고르기·행동 결정 (원작: 부대 상태 규칙 + 원작 AI 재현 / 개선: 재설계) |
| 캠페인 | 캠페인 **그래프 실행기** (장 노드·분기·조건·플래그·합류/이탈 처리) | 그래프 데이터 자체 (원작: EXE 추출 그대로 / 개선: 재구성한 그래프) |
| 이야기 | 장면 재생 형식 (화자·줄·분기) | 대사 내용 (원작: dialogue.json 원문 / 개선: 새로 쓴 대사) |
| 세이브 | 저장 형식 틀 | 에디션별 구역 (`eclipse:original:*`, `eclipse:remake:*`), 서로 섞이지 않음 |

핵심은 **캠페인을 코드가 아닌 데이터 그래프로** 만드는 것. 지금 `scenes.json` post 단계(join·leave·swap·routes·flag·item)와
`battles.json` (route·cond·turn) 이 이미 그 재료다. 원작판은 이것을 그대로 쓰고, 개선판은 같은 형식으로 새 그래프를 쓴다.
장면 재구성(장 순서 변경, 새 분기, 장 합치기)이 코드 수정 없이 데이터로 가능해진다.

## 개선판 데이터를 어디에 두나
- 원작 추출물은 지금처럼 gitignore (저작권). 개선판은 우리가 쓰는 것이라 저장소에 커밋: `content/remake/` (campaign·scenes·lines·battles 덮어쓰기).
- 개선판 대사는 새로 쓴 문장만 저장. 원작 줄을 그대로 쓰는 곳은 줄 번호(`line: 123`)로만 참조 → 원작 문장이 저장소에 들어가지 않는다.
- 배치 변경은 원작 레코드 위에 덮어쓰기(`records["12-1"]` 의 그룹 추가·교체)로. 맵 자체는 원작 그대로 공유.

## 작업 순서 (안)
1. **엔진 분리**: main.ts(651줄)에서 렌더·입력·대화 재생기와 "규칙·AI·캠페인 결정"을 떼어 `Rules`/`Ai`/`Campaign` 인터페이스 뒤로. 동작은 그대로.
   지금 코드는 작아서(총 1,068줄) 지금 나누는 게 가장 싸다.
2. **원작판 = 현재 동작 + 확정된 원작 규칙**: 행동 순서를 원작 민첩 키로 (보류 중이던 결정이 에디션으로 풀림). 피해 공식 등 미확정 부분은 [근사] 표시를 달고 원작판에 둔 채
   EXE 역분석으로 채운다 → 원작판을 위해 4단계 역분석 범위가 전투 공식·경험치·AI 까지 늘어난다.
3. **개선판 = 원작판 복제로 시작**: 처음엔 같은 데이터를 가리키고, S2 제안·6단계 재설계를 개선판에만 쌓는다.
4. 타이틀 메뉴: 판 선택 → 새로 시작/이어하기/장 선택(클리어 후)/크레딧(팬 게임 고지).
5. 확인: `pnpm check` + 두 판 각각 1장 자동 진행 스모크 테스트 (`?ed=original&stage=1`, `?ed=remake&stage=1`).

## 정할 것
- 판 선택을 런타임(타이틀 메뉴, 배포 하나)으로 할지, 빌드 두 개(배포 두 곳)로 할지 — 추천: 런타임
- 원작판의 충실도 목표: "원작 규칙 그대로" 인지 "원작 규칙 + 편의 기능(위협 범위 표시·되돌리기 등)" 인지 — 편의 기능은 엔진 공통이라 끄고 켜는 옵션으로 둘 수 있다
- 개선판 대사 파일(`content/remake/`)을 커밋해도 되는지 (저장소 공개 여부)
