# 원작 파일 포맷 (확정된 것만 기록)

## FRT 이미지 컨테이너 — 확정
파일 확장자 무관. 시그니처 `FRT`(일부 `FGT`, 예: ECP03.ECP). 모든 정수 little-endian.
```
파일 헤더 (45B): "FRT" + 이름[40] ('9'로 채움) + u16 count
항목 × count:
  "FRT" + 이름[40]           43B
  u16 a (항상 1)  u8 hasPal (항상 1)  u16 w  u16 h  u32 size   11B
  팔레트 768B (hasPal==1): VGA 6비트 RGB ×256 → ×4 해서 8비트로
  픽셀 데이터 size B: PCX식 RLE — b>=0xC0 이면 (b&0x3F)회 다음 바이트 반복, 아니면 리터럴. w*h 바이트 인덱스.
```
- 항목마다 자체 팔레트가 있다. **투명색 = 팔레트 255번** (흰색), 스프라이트 시트의 프레임 구분선 = 12번 (빨강).
- 같은 포맷이 아닌 것: `FRTWND`/`FRTBTN` 시그니처 (`ECPBAS/BUT/COM/LEV/MAG/MAI/SPE.ECP`, `MAIN.ECP`) = UI 창/버튼 정의, 구조 미분석.

## ECLIPSE.LML 스테이지 맵 — 확정 (`tools/stage.py`)
레코드 2000B × 43 (스테이지 n = 레코드 n-1).
```
+0  u16 0, u16 614, u16 타일수, u16 타일W(56), u16 타일H(48), u16 1, u16 맵W, u16 맵H
+24 원본 타일셋 파일명 ("DDT01.FGT")    +36~99 공통 상수(의미 미상)
+100           레이어1 W*H u8 : 타일 번호
+100+W*H       레이어2 W*H u8 : 0 평지 / 2 숲·바위 / 4 절벽 (추정: 장애물 등급)
+100+2*W*H     레이어3 W*H u8 : 3~6 지형 종류 (추정, 6 = 절벽·밀림)
```
타일 이미지 = `ECPnn.ECP` 의 마지막을 제외한 시트들. 시트당 11열, 타일 (1+57c, 1+49r) 위치에서 56×48 잘라냄, 시트 순서대로 번호 매김. 마지막 시트는 미니맵.

## ECLIPSE1/2.PAD 유닛 종류 표 — 확정
u16 개수(111) + 레코드 118B × 111. 이름 시작 b = 8+i*118. 레코드 = 런타임 유닛 구조체(0x76B) 그대로, **b+N = 런타임 +N+6**. 이름 CP949 10B, 이후 u16 필드 (b 기준): +10 id, +12 초상화, +16 직업?, +18 진영? (0 주인공, 1 아군, 2 적 추정), +24 레벨, +26 생명(HP), +30 역량(공격), +34 방어, +38 미상(전부 0), +42 정신, +46 민첩, +50 이동력. 능력치 이름은 장비 능력치 스위치로 [확정] (아래 EAD). `tools/units.py`
- 2026-10-12 정정: 예전 표기 +30 MP / +42 공격 / +46 방어 는 틀렸음. 런타임은 (최대, 현재) 쌍: +0x20/22 생명, +0x24/26 역량, +0x28/2a 방어, +0x2c/2e 미상, +0x30/32 정신, +0x34/36 민첩, +0x38 이동, +0x3a 피로, +0x44/46 무기 f2/f3 (무기 없으면 1/0), +0x48 체력(용도 미상)
- 장비 [확정]: +78/+80 무기, +82/+84 방어구, +86/+88 도구 = (EAD 세부 종류, EAD id), id 0 = 없음. 두 표 343건 모두 EAD 와 일치.
- 마법 [확정]: +90 마법 사용 가능(1/0), +92 개수(최대 8), +94~ MAD id 목록. 예: 리사 = 얼음화살·수료법·얼음기둥.
- 미분석: +54~+60 (작은 값, 종족·이동 종류 추정).
- PAD1 과 PAD2: 같은 111종, 같은 순서. 58종에서 레벨·HP·공방 등 수치를 소폭 조정 (높아지기도 낮아지기도 함) → 난이도 차이가 아닌 1부/2부용 표로 추정 (FVT·SAV·SLI 도 1/2 로 나뉨).
0~28 주인공 계열(일부 전직 전/후 중복), 29~91 일반 적·몬스터, 92~110 보스·NPC.

## ECLIPSE.EAD 장비·도구 표 — 부분 확정 (`tools/tables.py`)
u16 개수(182) + 레코드 30B. 필드(u16, 레코드 기준): +0 분류, +2 세부 종류, +4 이름 CP949 10B, +14 id(1부터), +16 f1, +18 f2, +20 f3, +22 kind, +24 value, +26 x1, +28 x2.
- 분류 0 = 무기 (id 1~104, 세부 1~18 = 무기 18종류), 1 = 방어구 (105~142, 세부 19~23 = 5종류), 2 = 도구·장신구 (143~182, 세부 24~30). 박스 표기 수치와 정확히 일치.
- (kind, value) = 주 능력치 (번호, 보정량), (x1, x2) = 부 능력치 (번호, 보정량) [구조 확정]. kind 0 = 효과 없음 (지도·미지의책 = 이벤트 아이템).
- 능력치 번호 [확정, 2026-10-12]: 이름표 EXE DS:0x1194 = 0 없음, 1 생명, 2 정신, 3 역량, 4 방어, 5 마법, 6 이동, 7 민첩, 8 체력. **9~16 = 1~8 감소** (장비 정보창 124e:9bcb: >8 이면 8 빼고 '-' 빨강).
  적용 함수 `0aa2:179d(unit, 해제?, items)`: 장비 6칸(무기·방어구·도구 × 주/부) 순회, 번호별 런타임 필드 가감 (PAD 항 참고). 5·13 마법 = 효과 없음, 8 체력 = +0x48 대입, 16 = +0x48 더함, 15 = 민첩 최대치를 두 번 뺌 (원작 버그, 쓰는 장비 없음). 해제면 부호 반대. 장착이면 끝에 현재치 = 최대치.
  전투 로드(124e:2062)에서 일행 외 모든 부대에 적용 → **실제 능력치 = PAD 기본값 + 장비 보정**. 일행은 합류·장비 변경 때 적용.
  쓰임 예: 6 이동+1 (뢰신의공·신비의장·영의갑옷·풍의악장·사신상), 9 생명− (사신상 8, 악마의눈 10), 10 정신− (주수정 6), 11 역량− (귀면갑옷 5), 12 방어− (일격권투 4)
- f2·f3 = 공격 방식 추정: f2 1 근접 / 2~3 원거리(활, 2·3 = 사거리?), f3 1 창·포 / 2 하프. 모두 0 = 장비 시 공격 없음(부적·지팡이 등).

## 유닛 애니메이션 ECPnn.MOV / FIG / MAG — 확정

## ECLIPSE.BAD 스테이지 배치 — 확정 (`tools/bad.py`, 2026-10-12)
레코드 300B × 129, EXE 는 앞 252B(126 u16) 만 읽음. **레코드 = (스테이지-1)*3 + 루트(0~2)**.
전투 순서표 = EXE DS:0x204a 바이트 30×3: route[i][j] = i번째 전투(1~29)·루트 j 의 장 번호 (값 그대로, 0행은 빈 칸). 1~9전은 세 루트 공통,
10전부터 갈라짐 (10전 = 10/12/13장, 9장 후 진로선택과 맞음). 루트 A·B 29전, C 28전 (29행은 43 중복). 43장 전체는 세 루트 합. 루트별 장 목록 `python tools/story.py routes`. 쓰이지 않는 (스테이지,루트) 칸은 1~10장 레코드 사본.
루트를 무엇이 정하는지는 미확인 (EXE 2ff8:0068 함수의 지역 [bp-0x13e], 저장 구조체 일부로 추정. SAV 는 암호화돼 있음).
u16 필드 (위치 p = y*맵W + x):
```
w0        스테이지 번호 (=맵 번호)          w1~10 항상 0
w11~18    주인공 일행 출전 칸 (0 = 없음, 최대 8)
w19       동료/NPC 수, w20~ 종류, w27~ 위치, w33 플래그(미상, 3)   예: 루이스·페니·시종관
w34       적 무리 수 (최대 4)
w35+9k    무리 k: 수 n, w36+9k~ 종류 ×8, 위치 w72+9k~ ×8  (w71+9k 항상 0)
w107+k    무리 k 활동 여부 1/0 [추정: 0 = 처음엔 대기]
w111      숨은 보물 수, w112~ 도구 id, w117~ 위치 [추정: 아이템 이름이 도구 범위]
w121      보상 수, w122~ 도구 id [추정]
```
검증: 사용되는 86개 레코드 모든 위치가 맵 안, 겹침 1건, 미해석 필드 0. 적 종류 대부분 29~91(일반), 보스 22.
출전 칸에 누가 들어가는지(초기 일행)는 이 파일에 없음.

## ECP.EXE
MZ 16비트, Borland C++ 1994. 사운드 Info-Sound TCSND/VOICE 드라이버. 클래스명 단서: `TroopsData`, `LxAiDecide`, `LxAiSearch`, `LxMapData`, `fxChineseDC`.
EXE가 여는 파일명 목록은 오프셋 0x5cd0c~ 근처 문자열.
- 오버레이·압축 없음. 헤더 1408문단(0x5800) 뒤 이미지, 재배치 5196개. DGROUP = 세그 0x573a (13.7KB). 나머지 세그먼트는 전부 코드.
- 분석 도구: `tools/exe.py` (capstone 16비트. `dis SEG:OFF n`, `fn SEG:OFF n` 함수 처음부터, `sweep(seg)`). Ghidra 대신 사용.
- 2ff8:0068 = 캠페인 진행 루프 (전투 순서표 사용), 0a19:015c = 전투 로드 (BAD 읽기).

## 대화 장면·전투 흐름 (ECP.EXE 하드코딩) — 확정 (`tools/script.py`, 2026-10-12)
장면 함수 `0aa2:4138(scene, phase)`: phase 별 블록 안에서 `cmp si, scene` 으로 분기, 대사 호출이 즉치값으로 박혀 있다.
- `0aa2:2ed2` 주고받기: DS 레코드 6B {인물A u8, 인물B u8, 줄A u16, 줄B u16}
- `0aa2:2da8` 단독 (인물, 줄) / `0aa2:310a` 범위: A·B 가 줄 start 부터 번갈아, A 직후 줄==end 이거나 n번 주고받으면 끝 / `0aa2:2b55` 직접 = 초상화 없는 줄
- 인물 = ECLIPSE2.PAD 유닛 번호 (=units.json id), 줄 = ECLIPSE.FNT 번호. 장면 번호 = 스테이지 또는 스테이지*10+k (같은 시점 여러 장면)
- phase 0 = 전투 시작: `124e:c3da` 의 switch(stage), 점프표 124e:d42b (43개)
- phase 1 = 전투 중 트리거: `124e:d4a7` 함수, 특정 유닛 +0x22(HP 추정)==0 일 때 (35·36·43·381·382장면). 유닛 구조체 0x242B
- phase 2 = 전투 후: 캠페인 루프 `2ff8:1900` 안의 "현재 스테이지 == S" 블록. 동료 합류 = `inc [bp-0x1c3]` 후 일행 배열에 유닛 추가 (+ `124e:73d3`, 알림 `0aa2:179d`)
- 초기 일행 = 아리크스(0)·레스다(18)·소피아(27) (2ff8:1681). 8장 후 아리크스·루이스로 재설정, 37장 후 일행[0] = 유닛 1 (아리크스 2차)
- **루트 = 9장 후 "진로선택" 메뉴** (`0aa2:0b0d`, 결과 0~2 → [bp-0x13e]). 조건 분기 아님 (선택지 문구는 EXE 문자열에 없음 — 그래픽 추정)
- 9장 후 선택지 "금괴조각주기"(`0aa2:0c58` 예/아니오): 예 → 줄 99~104, 깨진금괴(180) 회수·요정피리(168) 지급 / 아니오 → 105~107
- 쓰이는 줄 359/440. 안 쓰이는 줄 대부분은 쓰이는 대화의 거의 같은 사본 (182·188, 230~243, 280·290~297, 337~350, 360~377, 387~404 — 루트별 사본을 만들어 두고 연결 안 한 것으로 추정).
  그 외 137~139·422·439 는 범위 대화의 n/end 가 짧아 잘린 것 (원작 버그 추정)
- 전투 후 블록 안의 조건 [확정, 2026-10-12]: `cmp [bp-0x13e], N` = 루트 (je 로 이어지면 OR) → post 항목 `routes`.
  예 16장 장면 161/162/163 = 루트 A/B/C, 20장 A 페니(4) 합류·장면 201 / C 아티스 합류·장면 202, 26장 B 아티스 합류·장면 262 / A·C 261, 15장 니크로스는 C 만.
